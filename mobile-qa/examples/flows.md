# EXAMPLE — flows.md (정상 플로우 + 합격 기준)

> **Language note (English, deliberately).** Plugin prose is English, but this
> file is an *example of a layer-3 project artifact*: the project writes it, in
> the project's own language, and only that project's QA agents read it. SRR is a
> Korean project, so this example is Korean. Copy it to
> `$PROJECT_ROOT/.claude/mobile-qa/flows.md` and write yours in whatever language
> your team uses — but keep the status keywords (`PASS`/`FAIL`/`BLOCKED`) English,
> because the report contract parses them.

> **이 문서의 목적**: 범용 QA 에이전트는 "이 앱이 무엇을 해야 하는지" 모른다.
> 여기에 적힌 것이 **기대 동작의 유일한 근거**다. 여기 없는 기준으로 FAIL을 판정하면 안 된다.
>
> `screens.md`가 "무엇이 있는가"라면, 이 문서는 "무엇이 옳은가"다.

## 작성 형식

플로우마다: **목적 · 사전조건 · 단계 · 합격 기준 · 합격이 아닌 것(오탐 방지) · 아티팩트**

합격 기준은 **관찰 가능한 것**으로 쓴다. "잘 동작한다"가 아니라
"`notification-btn`이 보인다"처럼 에이전트가 확인할 수 있는 형태여야 한다.

**단계는 의도만 쓰고 조작 방법은 쓰지 않는다.** 탭·입력·대기 방식은 agent-device가
소유한다. 여기에 좌표나 명령어 문법을 적으면 드라이버 버전이 올라갈 때마다 썩는다.

## 검증된 플로우는 `.ad` 스크립트로 고정한다

플로우가 실제로 통과한 것이 확인되면, 그 세션을 **재생 가능한 아티팩트**로 남긴다.
매번 에이전트가 화면을 탐색하며 같은 경로를 다시 찾아내는 것은 턴 낭비이고, 무엇보다
**실행할 때마다 경로가 달라져 회귀 판정의 기준이 되지 못한다.**

- 저장 위치: `$PROJECT_ROOT/.claude/mobile-qa/artifacts/<FLOW-ID>@<appVersion>.ad`
- **파일명에 앱 버전을 박는다.** UI가 바뀌면 스크립트는 조용히 틀린 것이 아니라
  divergence로 **실패해야** 한다. 버전 없는 `login.ad` 한 개를 계속 덮어쓰면
  "언제부터 이 경로가 바뀌었는가"를 영영 알 수 없다.
- 녹화/재생/divergence 처리 문법은 여기 적지 않는다 —
  `agent-device help scripting`이 설치된 버전 기준의 정답이다.
- CI로 내보낼 때는 Maestro YAML로 export할 수 있다 (`replay export`).
- **비밀번호가 들어가는 단계는 녹화 대상에서 제외하거나 secret-safe fill을 쓴다.**
  순진하게 녹화하면 자격증명이 커밋되는 파일에 박힌다.
- 아티팩트는 **보조 수단이지 합격 기준이 아니다.** 합격 기준은 아래 각 플로우의
  `합격 기준` 항목이고, `.ad`는 거기 도달하는 빠른 길일 뿐이다.
  스크립트가 divergence로 실패했다고 곧바로 앱 버그로 판정하지 않는다 —
  UI 변경일 수도 있으므로 사람이 스크립트를 갱신할지 결정한다.

각 플로우의 `아티팩트` 항목에 현재 검증된 스크립트를 적는다. 없으면 `없음 (탐색 실행)`.

## FLOW-1: 이메일 로그인

- **목적**: 기존 계정으로 로그인해 메인탭에 진입한다.
- **사전조건**: 로그아웃 상태. 자격증명은 `MOBILE_QA_EMAIL` / `MOBILE_QA_PASSWORD`.
- **단계**:
  1. `InitialScreen`에서 `log-in-link` 진입 (**`loginEntryMarkers`에 있는 것만 누른다**)
  2. `email-input`에 이메일 입력
  3. `password-input`에 비밀번호 입력
  4. `login-next-btn` 제출
- **합격 기준**: 4~6초 내에 `notification-btn`이 관찰된다 (언어 무관 testID이므로 가장 신뢰도가 높다).
- **합격이 아닌 것 (오탐 주의)**:
  - 로그인 직후 dev LogBox 빨간 오버레이가 뜨는 것 자체는 FAIL이 아니다 (dev 로깅).
    다만 오버레이의 에러 텍스트는 보고서에 기록한다.
  - **화면이 바뀐 것만으로 성공 판정하지 않는다.** 약관 동의, 강제 업데이트,
    검증 에러 모두 화면을 바꾸지만 로그인은 아니다. `notification-btn`으로만 판정한다.
- **아티팩트**: 없음 (탐색 실행) — 자격증명이 포함되므로 녹화 시 secret-safe fill 필수.

## FLOW-2: 세션 유지 (앱 재시작)

- **목적**: 앱을 재시작해도 로그인 상태가 유지되는지 확인한다.
- **사전조건**: FLOW-1 완료 상태.
- **단계**: 앱 종료 → 재실행 → 화면이 안정될 때까지 대기
- **합격 기준**: 로그인 화면을 거치지 않고 곧바로 `notification-btn`이 관찰된다.
- **비고**: 이 동작 덕분에 대부분의 QA 세션에서 로그인 절차를 건너뛸 수 있다.
- **아티팩트**: 없음 (탐색 실행)

## FLOW-3: 메인탭 이동

- **목적**: 세 개 탭이 모두 진입 가능한지 확인한다.
- **사전조건**: 로그인 상태.
- **단계**: 별 탭 → 나의 수면 탭 → 마이 탭 순서로 이동
- **합격 기준**: 각 탭에서 크래시 없이 해당 화면이 렌더링된다.
  마이 탭에서는 `logout-btn`이 관찰된다.
- **합격이 아닌 것**: 데이터가 비어 있는 상태(빈 목록/0건 표시)는 그 자체로 FAIL이 아니다.
  테스트 계정에 데이터가 없을 뿐일 수 있다.
- **아티팩트**: 없음 (탐색 실행)

## FLOW-4: 언어 전환 (ko ↔ en)

- **목적**: 언어 변경이 UI 전반에 반영되는지 확인한다.
- **사전조건**: 로그인 상태, 마이 탭.
- **단계**: `language-link` → `language-select-btn`으로 대상 언어 선택 → `language-confirm-btn`
- **합격 기준**: 확인 후 화면의 라벨이 선택한 언어로 바뀐다. 앱 재시작 후에도 유지된다.
- **비고**: 언어를 바꾸면 **텍스트 기반 마커가 전부 무효가 된다.**
  이 플로우 이후에는 화면 식별에 `testID`만 쓴다. **테스트 종료 시 원래 언어로 되돌린다** —
  되돌리지 않으면 다음 QA 세션이 예상과 다른 언어에서 시작한다.
- **아티팩트**: 없음 (탐색 실행)

## FLOW-5: 로그아웃 (**항상 마지막에**)

- **목적**: 로그아웃이 인증 화면으로 되돌리는지 확인한다.
- **사전조건**: 로그인 상태, 마이 탭. **다른 모든 시나리오가 끝난 뒤에 수행한다.**
- **단계**: `logout-btn` → 확인 대화상자가 뜨면 `alert-confirm-btn`
- **합격 기준**: `InitialScreen`으로 이동하고 `log-in-link` / `sign-up-link`가 관찰된다.
- **비고**: 이 플로우를 실행하면 세션이 사라져 다음 QA는 로그인부터 시작해야 한다.
- **아티팩트**: 없음 (탐색 실행)

## 자동 QA에서 제외하는 것

명시적 요청이 없으면 아래는 **수행하지 않는다.** 시도하면 턴만 태우고 실패한다.

- **회원가입** — 실제 이메일 인증 코드 수신이 필요하고, 실제 계정을 생성한다.
- **비밀번호 찾기/변경** — 실제 이메일 수신이 필요하고, 계정 비밀번호를 바꿔 이후 QA를 전부 깨뜨린다.
- **카카오 / Apple 로그인** — 외부 IdP 화면이라 앱 밖으로 나간다. `loginEntryMarkers`가 이것을 막는다.
- **회원탈퇴 (`withdraw-btn`)** — 되돌릴 수 없다.
- **시간 조건부 별(star) 화면** — 특정 시간대에만 진입 가능하다.
  진입 실패를 앱 버그로 단정하지 말고 시간 조건을 먼저 의심한다.
- **결제/구독** — 해당 없음.
