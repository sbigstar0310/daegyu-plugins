# EXAMPLE — flows.md (정상 플로우 + 합격 기준)

> 이것은 **샘플**이다. 실제로는 `$PROJECT_ROOT/.claude/mobile-qa/flows.md`에 프로젝트가 직접 작성한다.
>
> **이 문서의 목적**: 범용 QA 에이전트는 "이 앱이 무엇을 해야 하는지" 모른다.
> 여기에 적힌 것이 **기대 동작의 유일한 근거**다. 여기 없는 기준으로 FAIL을 판정하면 안 된다.
>
> `screens.md`가 "무엇이 있는가"라면, 이 문서는 "무엇이 옳은가"다.

## 작성 형식

플로우마다: **목적 · 사전조건 · 단계 · 합격 기준 · 합격이 아닌 것(오탐 방지)**

합격 기준은 **관찰 가능한 것**으로 쓴다. "잘 동작한다"가 아니라
"`MainTabs`의 `별` 탭이 보인다"처럼 에이전트가 확인할 수 있는 형태여야 한다.

---

## FLOW-1: 이메일 로그인

- **목적**: 기존 계정으로 로그인해 메인탭에 진입한다.
- **사전조건**: 로그아웃 상태. 자격증명은 `MOBILE_QA_EMAIL` / `MOBILE_QA_PASSWORD`.
- **단계**:
  1. `InitialScreen`에서 `log-in-link` 탭
  2. `email-input`에 이메일 입력
  3. `password-input`에 비밀번호 입력 (iOS는 키보드 Next로 포커스 이동 — 직접 탭 금지)
  4. `login-next-btn` 탭
- **합격 기준**: 4~6초 내에 `MainTabs`가 표시된다 (`notification-btn` 관찰 — 언어 무관하므로 가장 신뢰도가 높다).
- **합격이 아닌 것 (오탐 주의)**:
  - 로그인 직후 dev LogBox 빨간 오버레이가 뜨는 것 자체는 FAIL이 아니다 (dev 로깅).
    다만 오버레이의 에러 텍스트는 보고서에 기록한다.
  - 스크린샷상 비밀번호 필드가 비어 보이는 것은 FAIL이 아니다 (iOS SecureTextField 특성).

## FLOW-2: 세션 유지 (앱 재시작)

- **목적**: 앱을 재시작해도 로그인 상태가 유지되는지 확인한다.
- **사전조건**: FLOW-1 완료 상태.
- **단계**: 앱 terminate → 재실행 → 4초 대기
- **합격 기준**: 로그인 화면을 거치지 않고 곧바로 `MainTabs`가 표시된다.
- **비고**: 이 동작 덕분에 대부분의 QA 세션에서 로그인 절차를 건너뛸 수 있다.

## FLOW-3: 메인탭 이동

- **목적**: 세 개 탭이 모두 진입 가능한지 확인한다.
- **사전조건**: 로그인 상태.
- **단계**: `별`/`Star` → `나의 수면`/`Sleep` → `마이`/`My` 순서로 탭 (라벨은 현재 언어 설정에 따름)
- **합격 기준**: 각 탭에서 크래시 없이 해당 화면이 렌더링된다.
  `마이`/`My` 탭에서는 `logout-btn`이 관찰된다.
- **합격이 아닌 것**: 데이터가 비어 있는 상태(빈 목록/0건 표시)는 그 자체로 FAIL이 아니다.
  테스트 계정에 데이터가 없을 뿐일 수 있다.

## FLOW-4: 언어 전환 (ko ↔ en)

- **목적**: 언어 변경이 UI 전반에 반영되는지 확인한다.
- **사전조건**: 로그인 상태, `마이`/`My` 탭.
- **단계**: `language-link` → `language-select-btn`으로 대상 언어 선택 → `language-confirm-btn`
- **합격 기준**: 확인 후 화면의 라벨이 선택한 언어로 바뀐다. 앱 재시작 후에도 유지된다.
- **비고**: 언어를 바꾸면 **텍스트 기반 마커가 전부 무효가 된다.**
  이 플로우 이후에는 화면 식별에 `testID`만 쓴다. 테스트 종료 시 원래 언어로 되돌린다.

## FLOW-5: 로그아웃 (**항상 마지막에**)

- **목적**: 로그아웃이 인증 화면으로 되돌리는지 확인한다.
- **사전조건**: 로그인 상태, `마이`/`My` 탭. **다른 모든 시나리오가 끝난 뒤에 수행한다.**
- **단계**: `logout-btn` 탭 → 확인 대화상자가 뜨면 `alert-confirm-btn`
- **합격 기준**: `InitialScreen`으로 이동하고 `kakao-login-btn` / `log-in-link`가 관찰된다.
- **비고**: 이 플로우를 실행하면 세션이 사라져 다음 QA는 로그인부터 시작해야 한다.

## 자동 QA에서 제외하는 것

명시적 요청이 없으면 아래는 **수행하지 않는다.** 시도하면 턴만 태우고 실패한다.

- **회원가입** — 실제 이메일 인증 코드 수신이 필요하다.
- **비밀번호 찾기/변경** — 실제 이메일 수신이 필요하고, 계정 비밀번호를 바꿔 이후 QA를 전부 깨뜨린다.
- **카카오 / Apple 로그인** — 외부 IdP 화면이라 앱의 접근성 트리 밖이다.
- **시간 조건부 별(star) 화면** — 특정 시간대에만 진입 가능하다.
  진입 실패를 앱 버그로 단정하지 말고 시간 조건을 먼저 의심한다.
- **결제/구독** — 해당 없음.
